# Data

Three released tables, their inputs, and the checks run on them. The block
between the `checks` markers is generated by `make manifest` from
[MANIFEST.json](MANIFEST.json); everything else is written by hand.

## Layout

| Path | What it is | In git |
| --- | --- | --- |
| `raw/2015/`, `raw/2022/` | source PDFs | no (`make fetch`; pinned by `raw/MANIFEST.csv`) |
| `raw/MANIFEST.csv` | path, SHA-256, bytes, pages, download URL per PDF | yes |
| `interim/ocr/2022/*.jsonl.gz` | Apple Vision OCR, one record per page: every text box with pixel coordinates, the detected ruling lines, the rotation applied | yes |
| `2015/source/mukhiya_reservation_2015.csv` | the pooled repository's 2015 table, unchanged | yes |
| `2015/mukhiya_results.parquet` | 2015, one row per mukhiya seat | yes |
| `2022/mukhiya_results.parquet` | 2022, one row per mukhiya seat | yes |
| `2022/panchayat_samiti_results.parquet` | 2022 samiti seats (by-product) | yes |
| `external/lgd_jharkhand_village_gp.csv` | Jharkhand rows of an LGD village-to-GP file | yes |
| `checks/handcheck_2022.csv` | 30 random 2022 rows transcribed by eye from page images | yes |
| `checks/text_layer_2022.csv` | 2022 rows decoded from the PDFs' own Kruti Dev text layer, with their OCR counterparts | yes |

## 2022 columns (`2022/mukhiya_results.parquet`)

Names follow the pooled schema of in-rolls/local_elections where a column
exists there.

| Column | Meaning |
| --- | --- |
| `state`, `year`, `district` | `Jharkhand`, `2022`, district (English, from the file name) |
| `district_no` | the district's number in the state list (Garhwa 1 … East Singhbhum 24), as in the roman numeral printed in each identifier |
| `block_no` | block number printed in the identifier; numbering is per district and **differs from 2015's** in at least Dhanbad |
| `block` | block name, Devanagari; null where the gazette prints no name the parser could tie to the number |
| `block_source` | where `block` came from: `identifier` (printed in the row itself, Bokaro and Jamtara), `panchayat_samiti_rows` (the same gazette's samiti rows print number and name together), `page_heading` (a "प्रखण्ड-…" heading) |
| `gram_panchayat`, `gp_no` | GP name and number as printed in the identifier |
| `tier`, `tier_local` | `gp_head`, `mukhiya` |
| `caste_reservation` | `ST`, `SC`, `NONE` (unreserved), or `RESERVED`: printed only as आरक्षित with no category (Khunti, whose GPs all lie in a Fifth Schedule area; under PESA these are presumably ST seats, but the page does not say so and the value is not inferred) |
| `open_category` | the seat is printed as "खुली श्रेणी के सीट (Open Category Seat)". These are the seats that went to backward classes before OBC reservation was dropped for 2022. They are open to all, so `caste_reservation` is `NONE` |
| `woman_reserved` | 1 = महिला (reserved for a woman), 0 = अन्य (other), null when unread |
| `reservation` | label combining the two, in the pooled vocabulary (`ST Woman`, `Other than Woman`, …) |
| `reservation_raw` | the two printed cells re-spelled in standard Devanagari (`अनुसूचित जनजाति \| महिला`) |
| `winner` | elected person's name as printed, with OCR spill from neighbouring cells removed |
| `seat_id_raw` | the identifier cell as OCR read it, unaltered |
| `row_text_raw` | the rest of the row as OCR read it (name, post, caste, gender cells), unaltered |
| `ocr_min_confidence` | lowest Vision confidence among the row's boxes |
| `parse_flags` | list of problems noticed while reading the row (see below) |
| `script` | `devanagari` |
| `source_path`, `source_page` | the PDF (`data/raw/2022/...`) and 1-based page |
| `row_y0`, `row_y1` | the row's vertical extent on that page, in pixels at 200 dpi (400 dpi for Lohardaga), to crop it for review |

`parse_flags` values: `post_unread_tier_from_identifier` (the post cell was
unreadable; the row was taken as mukhiya because its identifier has the mukhiya
shape), `post_mukhiya_but_identifier_ward` (post reads मुखिया but the
identifier ends in a number, as Dhanbad's आसनबनी-1 does), `caste_unread`,
`woman_unread`, `winner_unread`, `low_quality_source` (every Lohardaga row; see
below).

## 2015 columns (`2015/mukhiya_results.parquet`)

The pooled table's 23 columns, unchanged except that `source_path` now points
at `data/raw/2015/...`. Two columns are added: `block_no_from_id` and
`gp_no_from_id`, the numbers printed in `seat_id_raw`. They are there because
the pooled `block_no` is blank on 32% of rows and `block` on 54%.

## How the 2022 table was read

1. **OCR, first and persisted.** Every page of the 24 gazettes (3,194 pages)
   was rendered at 200 dpi (Lohardaga 400) and read by Apple Vision, `hi-IN`,
   on-device. Pages stored sideways or upside down were turned upright. The
   boxes are cached per page, so nothing downstream ever re-runs OCR.
2. **Rows.** Each seat row is anchored on its identifier cell
   (`I गढ़वा/04/13-लमारी कला`). Every other box on the page goes to the
   identifier whose line it lies on, after correcting for the page's tilt, and
   the post, caste and gender cells are read by vocabulary.
3. **Tier.** The post cell decides (मुखिया, ग्राम पंचायत सदस्य, पंचायत समिति
   सदस्य, जिला परिषद सदस्य). The identifier's shape decides only when the post
   cell is unreadable.

## Coverage and known problems

Each figure below is taken from the check block further down.

- **Rows.** 2022 has 4,339 rows against 4,345 GPs. 17 districts match the LGD
  count exactly. Lohardaga has 75 against 66 (see below). The others are short
  by 1 to 7.
- **Some missing GPs are absent from the gazette itself.** Sahebganj's mukhiya
  pages skip GP 1/10 (हरप्रसाद) and 9/9 and 9/13, though the ward rows for 1/10
  are printed on page 67 (checked by eye on pages 24 and 32). Those seats were
  probably not filled at the general election. The other gaps listed at the
  bottom were not each opened, so whether they are the source's or the
  parser's is not known.
- **Lohardaga is unreliable.** It is a faint, fax-like scan with a small face
  and rows that do not line up across columns. Even at 400 dpi, Vision merges
  adjacent rows, so numbers repeat, names pick up neighbours, and a few rows
  are invented. All 75 of its rows carry `low_quality_source`. Re-keying it by
  hand from the 3 mukhiya pages would be the fix.
- **Repeated (block, GP) numbers.** 44 rows share a printed number with
  another row: Lohardaga 32, Pakur 6, Sahebganj 2, Gumla 2, West Singhbhum 2.
  All are kept and flagged `duplicate_key`. Picking the right one takes the
  page image.
- **Block names.** 423 rows have `block = null`: all of Dumka and Ramgarh,
  part of Koderma, Palamu and Deoghar. Their gazettes print the block's name
  nowhere the parser can tie to its number. Filling them from the 2015 table
  was tried and rejected: block numbers are not stable across the two years
  (Dhanbad's 2022 block 6 is बाघमारा; its 2015 block 6 is धनबाद).
- **Unread cells.** Winner 15, caste 15, gender 41 rows, each flagged.
- **`RESERVED`** appears only in Khunti (19 rows), whose gazette prints bare
  आरक्षित for some blocks and अनुसूचित जनजाति for others.
- **2015 is the pooled table, not re-read.** It covers 3,972 rows (91% of
  4,345). It has 10 rows for Simdega (94 GPs) and 59 for West Singhbhum (217),
  no GP names for Pakur, blank blocks on 54% of rows, some place names still in
  Kruti Dev residue (`गोमो उÙार`), and 6 repeated (district, block, GP) keys.
  The pooled notes give no cause for the missing 9%. Running this
  repository's 2022 pipeline on the 2015 PDFs, which are the same Form 23,
  would likely close most of it.
- **2015 vs 2022 shares.** Jamtara is 98% ST and 1% SC in 2022 against 78% and
  21% in 2015. All of Jamtara is a Fifth Schedule area, where PESA reserves the
  mukhiya post for STs, so 2022 is the plausible one and the 2015 table is
  suspect there. Garhwa's women's share is 60% in 2022 against 52%. The gender
  cell is the best-verified field in the table (30/30 by eye, 1,107/1,108
  against the text layer), so this is taken as real.

## Independent checks

- **Hand transcription.** 30 random rows (seed 20221018) were rendered as image
  strips by `build/handcheck_sheet.py` and transcribed by eye without the
  parsed values in view. Result: block, GP number, caste and gender 30/30;
  winner names 28/30 exact (0.994 character agreement); GP names 27/30 (0.989).
  Every miss is a single dropped anusvara or chandrabindu, ौ read as ो, or म
  read as न.
- **Text layer.** Five gazettes carry their text in Kruti Dev. Decoded without
  OCR (`year2022/text_layer.py`), all 1,148 of their mukhiya rows are in the
  OCR table under the same key. Caste agrees on 1,084/1,084 rows where the
  text layer could be read. Gender agrees on 1,107/1,108 aligned rows. The
  other 17 gender mismatches are rows where the simple text reader paired a
  name with the next row's identifier; on Ranchi pages 62 and 63 the image
  shows the OCR table was right. This check found one real bug before
  release: जन्जाति (with a halant) had been read as SC.
- **2015 name match.** Of the 3,924 2022 GPs in blocks where 2015 has named
  rows, 81.5% have an exact or near (ratio ≥ 85) name match in the same 2015
  block. Over all 4,339 rows the share is 73.7% in block and 77.3% in
  district. This previews the later link. It is held down by 2015's gaps and
  Kruti residue and by spelling drift (मझिगावा / मझिगांवा, बहियार कलां /
  बहियारकला).
